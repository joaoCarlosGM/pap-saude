Exemplo: ```text src/components/dashboard/ ``` ## Exemplo de componente ```tsx interface StatusCardProps { title: string value: string } export function StatusCard({ title, value, }: StatusCardProps) { return ( &lt;div className="rounded-xl border border-slate-200 bg-white p-4 shadow-sm"&gt; &lt;p className="text-sm text-slate-500"&gt; {title} &lt;/p&gt; &lt;strong className="text-2xl text-slate-900"&gt; {value} &lt;/strong&gt; &lt;/div&gt; ) } ``` Uso: ```tsx &lt;StatusCard title="Atendimentos hoje" value="18" /&gt; ``` Quando um padrão visual começar a aparecer repetidamente, avalie transformá-lo em um componente. --- # Responsividade Toda nova interface deve ser verificada em telas pequenas e grandes. O Tailwind utiliza breakpoints como: ```text sm: md: lg: xl: ``` Exemplo: ```tsx &lt;div className="grid grid-cols-1 gap-4 md:grid-cols-2 xl:grid-cols-4"&gt; ... &lt;/div&gt; ``` Comportamento aproximado: ```text Mobile → 1 coluna Tablet → 2 colunas Desktop → 4 colunas ``` Não considere uma página concluída apenas porque funciona no desktop. --- # Padrão visual O front-end do PAP Saúde utiliza principalmente: - tons neutros `slate`; - cartões brancos; - bordas `slate-200`; - sombras discretas; - cantos arredondados; - rosa como cor de destaque; - espaçamento consistente; - hierarquia tipográfica clara. Exemplo: ```tsx &lt;div className="rounded-xl border border-slate-200 bg-white p-6 shadow-sm"&gt; Conteúdo &lt;/div&gt; ``` Evite introduzir um padrão visual completamente diferente em uma única página sem que isso faça parte de uma mudança global de design. --- # Client Components Componentes que utilizam estado, eventos ou APIs específicas do navegador normalmente precisam da diretiva: ```tsx "use client" ``` Exemplo: ```tsx "use client" import { useState } from "react" export function Example() { const [open, setOpen] = useState(false) return ( &lt;button onClick={() =&gt; setOpen(!open)}&gt; Alternar &lt;/button&gt; ) } ``` Não adicione `"use client"` indiscriminadamente. Componentes que apenas renderizam informações podem permanecer como Server Components quando a arquitetura permitir. --- # Tipos TypeScript Tipos compartilhados devem preferencialmente ficar em: ```text src/types/ ``` Exemplo: ```ts export interface Patient { id: string name: string status: "normal" | "atencao" | "urgente" } ``` Uso: ```ts const patients: Patient[] = [ { id: "1", name: "Paciente demonstração", status: "normal", }, ] ``` Evite utilizar `any` quando a estrutura dos dados for conhecida. --- # Mocks Algumas páginas ainda utilizam dados simulados. Evite transportar referências de componentes React ou funções dentro de objetos. Evite: ```ts const item = { icon: Users, } ``` Prefira: ```ts const item = { icon: "users", } ``` E realize o mapeamento no Client Component: ```tsx const icons = { users: Users, calendar: Calendar, } const Icon = icons[item.icon] ``` Esse padrão evita problemas de serialização entre Server Components e Client Components. --- # Manutenção ## Localizando um componente Antes de modificar um componente compartilhado: ```bash grep -RIn "NomeDoComponente" src ``` Exemplo: ```bash grep -RIn "DashboardKpi" src ``` Isso permite descobrir quais páginas poderão ser afetadas. ## Procurando rotas antigas Durante refatorações: ```bash grep -RIn 'href="/config"' src ``` ```bash grep -RIn 'href="/casos"' src ``` ## Verificando identidade visual antiga A identidade correta do sistema é: ```text PAP Saúde ``` Para procurar referências antigas: ```bash grep -RIn "Salvia" src ``` Referências antigas devem ser analisadas e removidas quando não fizerem mais parte do sistema. ## Fluxo de manutenção recomendado 1.
